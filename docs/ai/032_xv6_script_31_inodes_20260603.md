# xv6 Kernel 31 코드 정리: Inodes

## 읽는 순서

- `docs/reference/scripts/ko/31-xv6-kernel-31-inodes-yzyCoL9SA2M.md`
- `kernel/fs.h`: on-disk file system format, `struct dinode`
- `kernel/file.h`: in-memory `struct inode`, file/device table
- `kernel/fs.c`: inode cache와 inode 연산
- `kernel/defs.h`: fs 관련 외부 함수 선언

## 핵심

inode는 파일의 이름이 아니라 파일의 metadata와 data block 위치를 담는 객체다. 디스크에는 `dinode` 배열로 저장되고,
커널 메모리에는 `struct inode` cache entry로 올라온다.

읽을 때 중요한 구분은 두 가지다.

```text
on-disk dinode:
  type, nlink, size, addrs처럼 파일 시스템에 영속 저장되는 정보

in-memory inode:
  dinode 사본 + dev/inum/ref/valid/lock 같은 커널 실행 중 관리 정보
```

## inode의 두 표현

inode는 이름 없는 파일 하나의 metadata다. 파일 이름은 디렉터리 엔트리에 있고, inode에는 type, link 수, size,
data block 주소가 있다.

디스크에는 `struct dinode`가 inode 배열에 연속 저장된다. `fs.h` 기준 필드는 `type`, `major`, `minor`, `nlink`, `size`,
`addrs[NDIRECT + 1]`이다. `IBLOCK(i, sb)`는 inode 번호 `i`가 들어 있는 디스크 블록을 계산한다.

메모리에는 `struct inode`가 inode cache entry로 존재한다. `dinode` 필드 사본에 더해 `dev`, `inum`, `ref`, `lock`,
`valid`가 있다.

```c++
struct inode {
  uint dev;
  uint inum;
  int ref;
  struct sleeplock lock;
  int valid;
  short type;
  short major;
  short minor;
  short nlink;
  uint size;
  uint addrs[NDIRECT + 1];
};
```

## inode cache 상태

`fs.c`의 `itable`은 `NINODE`개 in-memory inode cache와 이를 보호하는 spinlock이다. 현재 `kernel/param.h`의 `NINODE`는 50이다.

- `itable.lock`: cache entry 배정과 `dev`, `inum`, `ref`를 보호한다.
- `ref`: 이 in-memory inode entry를 잡고 있는 커널 포인터 수다. `ref == 0`이면 cache slot은 재사용 가능하다.
- `valid`: 디스크의 `dinode` 내용이 이 cache entry에 읽혀 왔는지 표시한다. `iget()`은 디스크를 읽지 않고, `ilock()`이 필요하면 읽고 `valid = 1`로 만든다.
- `ip->lock`: sleeplock이다. `valid`, `type`, `nlink`, `size`, `addrs`처럼 디스크 inode에서 온 필드와 파일 내용을 접근할 때 잡아야 한다.

전형적인 순서는 `iget(dev, inum) -> ilock(ip) -> inode 검사/수정 -> iunlock(ip) -> iput(ip)`이다. `iget()`과 `ilock()`이
분리되어 있으므로, open file이나 cwd처럼 오래 참조는 유지하되 실제 inode 내용 잠금은 짧게 잡을 수 있다.

## `nlink`와 `ref`

`nlink`는 파일 시스템 안에서 이 inode를 가리키는 directory entry, 즉 hard link 개수다. 디스크에 저장되는 metadata이며
`iupdate()`로 `dinode.nlink`에 반영된다.

`ref`는 메모리 inode cache entry에 대한 현재 참조 수다. 열린 파일, 현재 디렉터리, path lookup 중인 포인터 등이 `ref`를 증가시킨다.
디스크에는 저장되지 않는다.

파일 삭제 가능 조건은 둘을 함께 본다. `iput()`은 `ref == 1`, `valid == 1`, `nlink == 0`이면 마지막 메모리 참조가 사라지는
상황으로 보고 `itrunc()`로 data block을 해제한 뒤 `type = 0`을 디스크에 쓴다.

## 핵심 함수 흐름

`iinit()`은 `itable.lock`을 초기화하고 cache의 각 inode sleeplock을 초기화한다.

`iget(dev, inum)`은 `itable.lock` 아래에서 같은 `(dev, inum)` cache entry를 찾으면 `ref++` 후 반환한다. 없으면
`ref == 0` slot을 골라 `dev`, `inum`, `ref = 1`, `valid = 0`으로 만든다. inode 내용은 아직 읽지 않고 lock도 잡지 않는다.

`ialloc(dev, type)`은 디스크 inode 배열을 순회하며 `dip->type == 0`인 free inode를 찾는다. 찾으면 `dinode`를 0으로 지우고
`type`을 설정해 할당 표시를 한 뒤 `log_write()`하고, `iget(dev, inum)`으로 unlocked referenced inode를 반환한다.

`iupdate(ip)`는 memory inode의 on-disk 필드 사본을 `dinode`에 써서 disk에 반영한다. caller가 `ip->lock`을 잡고 있어야
하고, 실제 disk write는 `log_write()`로 transaction에 포함된다.

`ilock(ip)`은 `ip->lock` sleeplock을 잡는다. `valid == 0`이면 `IBLOCK(ip->inum, sb)`에서 `dinode`를 읽어 `type`,
`major`, `minor`, `nlink`, `size`, `addrs`를 채우고 `valid = 1`로 만든다. `type == 0`이면 panic한다.

`iunlock(ip)`은 현재 caller가 잡고 있는 `ip->lock`을 해제한다.

`idup(ip)`은 `itable.lock` 아래에서 `ref++`한다. `iunlockput(ip)`은 `iunlock(ip)` 뒤 `iput(ip)`을 호출하는 흔한 조합이다.

`iput(ip)`은 참조를 내려놓는다. 마지막 참조이고 link도 없으면 inode lock을 잡은 채 `itrunc(ip)`, `ip->type = 0`,
`iupdate(ip)`, `ip->valid = 0`을 수행한 뒤 `ref--`한다. 주석처럼 block free가 필요할 수 있으므로 transaction 안에서 호출되어야 한다.

`itrunc(ip)`은 direct block들을 모두 `bfree()`하고, indirect block이 있으면 그 안의 block 주소들을 모두 해제한 뒤 indirect block 자체도
해제한다. 마지막에 `size = 0`으로 만들고 `iupdate(ip)`를 호출한다.

`bmap(ip, bn)`은 파일 내부 block 번호 `bn`을 디스크 block 번호로 바꾼다. 해당 block이 아직 없으면 새 block을 할당한다.

- `bn < NDIRECT`: `ip->addrs[bn]` direct pointer를 사용하고, 비어 있으면 `balloc()`으로 채운다.
- `bn >= NDIRECT`: `bn -= NDIRECT` 후 `ip->addrs[NDIRECT]`가 가리키는 indirect block을 사용한다. indirect block 자체나 그 안의 entry가 비어 있으면 할당한다.
- indirect index가 `NINDIRECT` 이상이면 `panic("bmap: out of range")`다.

`readi(ip, user_dst, dst, off, n)`은 offset과 size를 검사하고, 읽을 범위를 `ip->size` 안으로 줄인다. 각 파일 block마다
`bmap()`으로 disk block을 얻고 `bread()`한 뒤 `either_copyout()`으로 kernel 또는 user 주소에 복사한다.

`writei(ip, user_src, src, off, n)`은 overflow와 `MAXFILE * BSIZE` 초과를 거부한다. 각 block마다 `bmap()`으로 필요 block을
할당하고 `either_copyin()`으로 buffer에 복사한 뒤 `log_write()`한다. loop 후 `off > ip->size`이면 size를 늘린다. size가
변하지 않아도 `bmap()`이 `addrs`를 바꿨을 수 있으므로 항상 `iupdate(ip)`를 호출한다.

`stati(ip, st)`는 locked inode의 `dev`, `inum`, `type`, `nlink`, `size`를 `struct stat`으로 복사한다.

## direct/indirect block과 size 업데이트

현재 repo의 `fs.h`는 `NDIRECT = 12`, `NINDIRECT = BSIZE / sizeof(uint)`, `MAXFILE = NDIRECT + NINDIRECT`를 쓴다.
`BSIZE`가 1024이고 block number가 `uint`이므로 indirect block 하나에는 256개 주소가 들어간다. 최대 파일 크기는
`(12 + 256) * 1024` byte다.

`writei()`가 파일을 늘릴 때 흐름은 다음과 같다.

```text
writei
-> bmap(file block number)
   -> direct pointer 또는 indirect pointer 할당
   -> 필요하면 data block 할당
-> buffer cache block에 데이터 복사
-> log_write(data block)
-> off가 기존 size보다 커졌으면 ip->size 갱신
-> iupdate(ip)로 size와 addrs를 dinode에 기록
```

`readi()`도 `bmap()`을 호출하므로 hole을 읽는 용도에는 맞지 않는다. 다만 xv6의 일반 흐름에서는 sparse file을 만들지 않고,
읽기는 `off + n`을 `ip->size`로 제한한다.

## 현재 repo 차이

- 강의는 `fs.c`의 low-level 함수들이 직접 transaction을 시작하지 않는다고 설명한다. 현재 repo의 `ireclaim()`은 예외적으로
  `begin_op()`/`end_op()`를 호출해 orphaned inode를 부팅 시 회수한다.
- 현재 `fsinit()`은 superblock을 읽고 log를 초기화한 뒤 `ireclaim(dev)`를 호출한다. 강의 스크립트의 inode 개요에는 이 부팅 시 orphan reclaim 흐름이 없다.
- 현재 `ialloc()`은 free inode가 없으면 panic이 아니라 `printf("ialloc: no inodes\n")` 후 `0`을 반환한다. `balloc()`과
  `bmap()`도 공간 부족 경로에서 `0`을 반환할 수 있다.
