# xv6 Kernel 4 코드 정리: Spinlocks

## 읽는 순서

- `kernel/spinlock.h`: spinlock 자료구조
- `kernel/spinlock.c`: `initlock`, `acquire`, `release`, `holding`, `push_off`, `pop_off`
- `kernel/proc.h`, `kernel/proc.c`: CPU별 상태와 `mycpu()`

## `kernel/spinlock.h`

```c
// 상호 배제를 위한 lock.
struct spinlock {
  uint locked; // lock이 잡혀 있으면 1, 풀려 있으면 0

  // 아래 필드들은 correctness보다는 debugging을 위한 정보다.
  char *name;      // lock 이름
  struct cpu *cpu; // 이 lock을 잡고 있는 CPU
};
```

스핀락의 실제 상태는 `locked` 하나로 충분하다. `name`과 `cpu`는 panic 메시지나 `holding()` 검사처럼
문제를 빨리 찾기 위한 보조 정보다.

## `kernel/proc.h`: CPU별 interrupt nesting 상태

```c
// CPU마다 하나씩 있는 상태.
struct cpu {
  struct proc *proc;      // 이 CPU에서 현재 실행 중인 process, 없으면 null
  struct context context; // scheduler로 들어가기 위한 swtch() 저장 위치

  // push_off()/pop_off()가 중첩 호출될 수 있으므로 깊이를 기록한다.
  int noff;               // push_off() nesting depth

  // 첫 push_off() 이전에 interrupt가 켜져 있었는지 저장한다.
  // 마지막 pop_off()에서 이 값이 true이면 interrupt를 다시 켠다.
  int intena;
};

extern struct cpu cpus[NCPU];
```

`noff`와 `intena`는 스핀락 자체보다 `push_off`/`pop_off`를 정확히 맞추기 위한 상태다. 스핀락을 여러 개
중첩해서 잡아도, 마지막 락을 풀기 전에는 interrupt가 다시 켜지면 안 된다.

## `kernel/proc.c`: 현재 CPU 찾기

```c
// interrupt가 꺼진 상태에서 호출해야 한다.
// 그렇지 않으면 process가 다른 CPU로 옮겨지는 상황과 race가 생길 수 있다.
int
cpuid()
{
  int id = r_tp(); // start.c가 tp에 hart id를 저장해 두었다.
  return id;
}

// 현재 CPU의 struct cpu를 반환한다.
// interrupt가 꺼진 상태여야 현재 CPU가 안정적으로 유지된다.
struct cpu *
mycpu(void)
{
  int id = cpuid();
  struct cpu *c = &cpus[id];
  return c;
}
```

`acquire()`는 시작하자마자 `push_off()`로 interrupt를 끈다. 그 뒤 `mycpu()`를 호출하므로 현재 CPU
구조체를 안전하게 얻을 수 있다.

## `kernel/spinlock.c`: 초기화

```c
// 상호 배제 spin lock.

#include "types.h"
#include "param.h"
#include "memlayout.h"
#include "spinlock.h"
#include "riscv.h"
#include "proc.h"
#include "defs.h"

void
initlock(struct spinlock *lk, char *name)
{
  lk->name = name; // debugging용 이름
  lk->locked = 0;  // 처음에는 unlocked
  lk->cpu = 0;     // 아직 이 lock을 가진 CPU가 없다.
}
```

## `kernel/spinlock.c`: `acquire`

```c
// lock을 획득한다.
// lock을 얻을 때까지 tight loop를 돌기 때문에 spinlock이라고 부른다.
void
acquire(struct spinlock *lk)
{
  // 같은 CPU에서 interrupt handler가 같은 lock을 잡으려 하면 deadlock이 날 수 있다.
  // 그래서 lock을 시도하기 전에 현재 CPU의 interrupt를 끈다.
  push_off();

  // 같은 CPU가 이미 들고 있는 lock을 다시 acquire하려 하면 버그다.
  if (holding(lk))
    panic("acquire");

  // RISC-V에서 __atomic_exchange_n은 atomic swap으로 컴파일된다.
  //
  //   a5 = 1
  //   s1 = &lk->locked
  //   amoswap.w.aq a5, a5, (s1)
  //
  // 의미:
  //   1. lk->locked에 1을 쓴다.
  //   2. 동시에 이전 값을 가져온다.
  //   3. 이 read/write 사이에 다른 CPU가 끼어들 수 없다.
  //
  // 이전 값이 0이면 내가 lock을 얻은 것이다.
  // 이전 값이 1이면 누군가 이미 들고 있으므로 계속 반복한다.
  //
  // __ATOMIC_ACQUIRE는 compiler와 processor가
  // critical section의 load/store를 이 지점 앞으로 옮기지 못하게 한다.
  while (__atomic_exchange_n(&lk->locked, 1, __ATOMIC_ACQUIRE) != 0)
    ;

  // holding()과 debugging을 위해 lock 소유 CPU를 기록한다.
  lk->cpu = mycpu();
}
```

여기서 가장 중요한 줄은 `__atomic_exchange_n`이다. 단순한 `if (locked == 0) locked = 1`은 두 CPU가
동시에 성공할 수 있으므로 사용할 수 없다.

## `kernel/spinlock.c`: `release`

```c
// lock을 해제한다.
void
release(struct spinlock *lk)
{
  // 내가 들고 있지 않은 lock을 release하면 버그다.
  if (!holding(lk))
    panic("release");

  // 이제 더 이상 이 CPU가 소유자가 아니다.
  lk->cpu = 0;

  // lock 해제는 논리적으로 lk->locked = 0과 같다.
  //
  // 다만 C 표준만 놓고 보면 단순 assignment가 여러 store로 구현될 가능성을
  // 완전히 배제하지 않는다. xv6는 atomic store를 명시적으로 사용한다.
  //
  // RISC-V에서는 대략 다음처럼 단일 store와 fence가 생성된다.
  //
  //   fence rw,w
  //   sw zero,0(s1)
  //
  // __ATOMIC_RELEASE는 critical section 안의 메모리 접근이
  // lock 해제 뒤로 밀리지 않게 한다. 다른 CPU가 lock을 얻었을 때,
  // 이전 CPU의 수정 내용이 이미 보이도록 만드는 데 중요하다.
  __atomic_store_n(&lk->locked, 0, __ATOMIC_RELEASE);

  // acquire에서 끈 interrupt 상태를 원래대로 복구한다.
  pop_off();
}
```

`release()`는 단순히 `locked`를 0으로 만드는 함수처럼 보이지만, 실제로는 메모리 순서와 interrupt
nesting 복구까지 책임진다.

## `kernel/spinlock.c`: `holding`

```c
// 현재 CPU가 이 lock을 들고 있는지 확인한다.
// mycpu()를 안정적으로 호출해야 하므로 interrupt는 꺼져 있어야 한다.
int
holding(struct spinlock *lk)
{
  int r;
  r = (lk->locked && lk->cpu == mycpu());
  return r;
}
```

`holding()`은 재진입 acquire, 잘못된 release 같은 버그를 찾는 안전장치다.

## `kernel/spinlock.c`: `push_off`와 `pop_off`

```c
// push_off/pop_off는 intr_off()/intr_on()과 비슷하지만 짝을 맞춰 동작한다.
//
// 예:
//   push_off();
//   push_off();
//   pop_off();  // 아직 interrupt를 켜면 안 된다.
//   pop_off();  // 여기서야 원래 켜져 있었다면 다시 켠다.
//
// 또한 처음부터 interrupt가 꺼져 있었다면,
// push_off 후 pop_off를 해도 계속 꺼진 상태로 둔다.

void
push_off(void)
{
  int old = intr_get(); // push_off 이전 interrupt 상태

  // mycpu()를 쓰는 동안 비자발적 context switch가 일어나지 않게 interrupt를 끈다.
  intr_off();

  // 첫 push_off라면 원래 interrupt 상태를 저장한다.
  if (mycpu()->noff == 0)
    mycpu()->intena = old;

  // 중첩 깊이 증가
  mycpu()->noff += 1;
}

void
pop_off(void)
{
  struct cpu *c = mycpu();

  // pop_off 중에 interrupt가 켜져 있다면 짝이 깨진 심각한 오류다.
  if (intr_get())
    panic("pop_off - interruptible");

  // push_off보다 pop_off가 많아도 오류다.
  if (c->noff < 1)
    panic("pop_off");

  c->noff -= 1;

  // 마지막 pop_off이고, 처음 push_off 전에는 interrupt가 켜져 있었다면 복구한다.
  if (c->noff == 0 && c->intena)
    intr_on();
}
```

## 코드로 보는 전체 패턴

```c
acquire(&some_lock);

// 여기부터 critical section.
// 공유 자료구조는 이 구간 안에서만 안전하게 읽고 쓴다.
// 이 구간은 짧아야 하며 sleep하면 안 된다.

release(&some_lock);
```

스핀락은 짧은 임계 구역을 보호하는 도구다. 락을 잡은 채 오래 기다리거나 잠들면 다른 CPU가 바쁜 대기를
계속하게 되고, 커널 전체 성능이나 진행성이 깨질 수 있다.
