## 핵심 요약

xv6는 MIT에서 교육용으로 만든 작고 단순한 Unix-like 운영체제 커널이다. 실제 Linux나 Unix
커널처럼 복잡하고 거대한 시스템을 그대로 공부하기는 어렵기 때문에, xv6는 운영체제의 핵심 구조를
코드 수준에서 따라가기 좋은 학습 대상이다.

이 강의 시리즈는 xv6의 RISC-V 버전을 기준으로 한다. 보통 실제 RISC-V 하드웨어가 아니라 QEMU
에뮬레이터 위에서 실행하며, xv6 자체는 베어 머신에서 동작하는 멀티코어 운영체제로 설계되어 있다.

## xv6가 제공하는 기능

xv6는 짧은 코드베이스지만 Unix 계열 운영체제의 핵심 기능을 갖고 있다.

- 프로세스와 각 프로세스별 가상 주소 공간
- 각 주소 공간을 위한 페이지 테이블
- Unix-like 파일과 디렉터리 구조
- 파이프를 통한 프로세스 간 데이터 전달
- 타이머 인터럽트 기반 멀티태스킹
- `fork`, `wait`, `exit`, `exec`, `open`, `read`, `write` 등 21개 시스템 콜
- `sh`, `cat`, `echo`, `grep`, `kill`, `ln`, `ls`, `mkdir`, `rm`, `wc` 같은 기본 사용자 프로그램

즉 xv6는 실사용 OS로는 제한적이지만, 운영체제의 큰 흐름을 이해하기에는 충분한 기능을 제공한다.

## xv6에 없는 것

xv6는 의도적으로 많은 기능을 생략한다. 이 단순함 덕분에 전체 커널 구조를 공부할 수 있다.

- 사용자 ID, 로그인, 인증
- 파일 권한 비트
- 마운트와 여러 파일 시스템
- 디스크로의 메모리 페이징
- 네트워크와 소켓
- 풍부한 디바이스 드라이버
- 대규모 사용자 프로그램 생태계

현실의 운영체제는 훨씬 많은 기능과 예외 처리를 포함하지만, xv6는 핵심 메커니즘을 드러내는 데
초점을 둔다.

## 하드웨어와 실행 환경

xv6는 공유 메모리 멀티프로세서 환경을 가정한다. 여러 코어가 하나의 메인 메모리를 공유한다.
강의에서는 CPU, core, hart를 거의 같은 의미로 사용한다. RISC-V에서 hart는 hardware thread를
뜻하지만, xv6 학습에서는 하나의 실행 흐름을 수행하는 하드웨어 처리 단위라고 이해하면 충분하다.

xv6가 다루는 주요 장치는 다음과 같다.

- UART: 콘솔 입출력용 직렬 통신 장치
- 디스크: QEMU가 호스트 파일로 에뮬레이션하는 저장 장치
- 타이머 인터럽트: 각 코어별로 존재하며 스케줄링에 사용
- PLIC: 외부 장치 인터럽트를 어느 코어에 전달할지 관리하는 interrupt controller

xv6에서는 물리 메모리 크기가 128MB로 고정되어 있다. 실제 OS처럼 부팅 시 사용 가능한 전체 메모리를
동적으로 탐색하지 않는다.

## 메모리 관리

물리 메모리는 4KB 페이지 단위로 관리된다. 커널은 사용 가능한 페이지들을 단순한 free list로 보관하고,
필요할 때 페이지 하나를 꺼내 쓰며, 다 쓰면 다시 free list에 돌려놓는다.

가상 메모리는 페이지 테이블로 관리된다. xv6 RISC-V 버전은 Sv39 기반의 3단계 페이지 테이블을 사용한다.
각 프로세스는 자기만의 페이지 테이블을 갖고, 커널은 별도의 커널 페이지 테이블을 갖는다. 커널 페이지
테이블은 모든 코어가 공유한다.

페이지 테이블 엔트리에는 읽기, 쓰기, 실행, user 접근 가능 여부, valid 여부 같은 권한 정보가 들어간다.
이를 통해 어떤 페이지는 사용자 모드에서 접근 가능하고, 어떤 페이지는 커널 모드에서만 접근 가능하게 만들
수 있다.

## 사용자 주소 공간

사용자 프로세스의 가상 주소 공간은 대략 다음처럼 배치된다.

```text
                             MAXVA +---------------------------------+
                                   | TRAMPOLINE              -kr-x   |
         TRAMPOLINE = MAXVA-PGSIZE +---------------------------------+
                                   | TRAPFRAME               -krw-   |
 TRAPFRAME = TRAMPOLINE - PGSIZE   +---------------------------------+
                                   |                                 |
                                   | unused                  -----   |
                                   |                                 |
                             p->sz +---------------------------------+
                                   | heap                    ukrw-   |
                                   |              ^                  |
                                   |              |                  |
                                   |              |                  |
                         stack_top +---------------------------------+
                                   | user stack              ukrw-   |
                                   |              |                  |
                                   |              |                  |
                                   |              v                  |
                         stackbase +---------------------------------+
                                   | guard page              -k---   |
        PGROUNDUP(elf_end) = guard +---------------------------------+
                                   | data + bss              ukrw-   |
                                   |                                 |
                                   | text                    ukr-x   |
                              0x0  +---------------------------------+
```

권한 표기는 대략적인 읽기용 요약이다. 문자열 위치는 `ukrwx` 순서이며, 빠진 권한은 `-`로 표시한다.
예를 들어 `ukrw-`는 user 접근 가능, kernel 접근 가능, 읽기/쓰기 가능, 실행 불가를 뜻한다.

각 영역의 의미는 다음과 같다.

- `TRAMPOLINE`: trap/interrupt 진입과 복귀에 쓰는 코드 영역이다. 모든 프로세스가 같은 물리 페이지를 공유하고, user mode에서는 접근할 수 없다.
- `TRAPFRAME`: trap 발생 시 레지스터를 저장하는 영역이다. 가상 주소는 같지만 프로세스마다 별도의 물리 페이지를 가진다.
- `unused virtual address space`: xv6의 사용자 프로그램이 보통 사용하지 않는 큰 빈 가상 주소 범위다.
- `heap`: `sbrk` 등으로 확장되는 동적 메모리 영역이며 높은 주소 방향으로 자란다. 현재 끝은 프로세스의 `p->sz`로 관리된다.
- `user stack`: 사용자 프로그램의 스택이다. xv6에서는 `USERSTACK` 페이지로 고정되며, 스택 포인터는 높은 주소에서 낮은 주소 방향으로 내려간다.
- `guard page`: user stack 아래에 둔 접근 불가능 페이지다. stack overflow를 예외로 잡아내기 위해 사용한다.
- `data`: ELF에서 읽어 온 전역 변수와 초기화된 데이터가 놓이는 영역이다.
- `text`: ELF에서 읽어 온 사용자 코드가 놓이는 영역이다.

`stack_top`과 `stackbase`는 매크로가 아니라 `exec.c` 안에서 계산되는 값이다. 크기를 정하는 매크로는
`USERSTACK`과 `PGSIZE`이고, 높은 쪽 고정 매핑은 `MAXVA`, `TRAMPOLINE`, `TRAPFRAME` 매크로로 정해진다.

`exec` 시스템 콜은 ELF 실행 파일을 읽어 코드와 데이터를 사용자 주소 공간에 배치하고, 스택을 만든 뒤
프로그램 인자들을 스택에 올린다. xv6는 환경 변수는 지원하지 않고 `argc`, `argv`만 다룬다.

사용자 스택은 4KB 한 페이지로 제한된다. 스택이 guard page를 침범하면 예외가 발생하고 프로세스가
종료된다. trampoline과 trapframe은 트랩과 인터럽트 처리에 사용되며 사용자 모드에서는 접근할 수 없다.

## 스케줄링과 동시성

xv6의 스케줄러는 단순한 라운드 로빈 방식에 가깝다. 모든 코어는 하나의 프로세스 배열을 공유하고, 실행
가능한 프로세스를 찾기 위해 이 배열을 선형으로 훑는다. 엄밀한 의미의 완전한 라운드 로빈은 아니지만,
멀티코어 환경에서 단순하고 이해하기 쉬운 방식이다.

동시성 제어에는 주로 다음 기법이 사용된다.

- 스핀락: `acquire`와 `release`로 공유 자료구조 보호
- `sleep`과 `wakeup`: 조건이 만족될 때까지 프로세스를 재우고 다시 깨움
- 선택적 인터럽트 비활성화: 현재 코어에서 인터럽트에 의한 실행 중단을 막음

단, 한 코어에서 인터럽트를 꺼도 다른 코어의 실행은 막지 못한다. 멀티코어 공유 자료구조에는 여전히 락이
필요하다.

## 설계상 특징

xv6는 많은 값을 고정 크기 배열과 `#define` 상수로 관리한다. 프로세스 수, 열린 파일 수, 메모리 크기 같은
제한이 정적으로 정해져 있고, 많은 자료구조를 연결 리스트보다 배열과 선형 검색으로 처리한다.

이 방식은 확장성은 떨어지지만 코드가 단순하다. 그래서 xv6는 실전용 커널이라기보다 운영체제의 핵심
메커니즘을 작은 코드 안에서 관찰하기 좋은 학습용 커널이다.

## 정리

1번 스크립트는 xv6가 무엇이고 왜 공부할 만한지, 그리고 어떤 Unix-like 기능과 한계를 갖는지 소개한다.
2번 스크립트는 그 위에서 xv6가 가정하는 하드웨어 환경, 메모리 관리, 사용자 주소 공간, 스케줄링,
동시성 제어 방식을 더 구체적으로 설명한다.

두 내용을 합치면 xv6의 첫인상은 명확하다. xv6는 작은 커널이지만 프로세스, 시스템 콜, 파일 시스템,
가상 메모리, 인터럽트, 스케줄링이라는 운영체제의 핵심 주제를 모두 담고 있으며, 이후 코드를 따라가기 위한
전체 지도를 제공한다.
