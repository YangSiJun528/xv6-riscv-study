### MMIO가 메모리를 점유한다는 뜻

MMIO는 실제 RAM을 점유하는 것이 아니라 physical address space의 일부를 장치가 차지하는 것이다.
그래서 그 주소 범위는 일반 메모리로 사용할 수 없다.

다만 현대 시스템에서는 그 RAM 영역을 다른 물리 주소 범위로 재배치해서 실제 RAM 용량 손실을 피한다.

이 정보는 CPU가 스스로 아는 것이 아니라 하드웨어 플랫폼, 펌웨어, Device Tree, ACPI, PCI/PCIe 탐색 등을 통해 OS가 알게 된다.
xv6는 QEMU virt 플랫폼을 가정하고 `memlayout.h`에 UART, virtio, PLIC 주소를 하드코딩한다.

### Memory-Mapped I/O (MMIO) vs Port mapped IO (PMIO)
(생각난김에 하드웨어 I/O 방법 간단하게 정리)

(Port mapped IO는 Isolated IO라고 부르기도 한다. )

- Memory-Mapped I/O
    - I/O 장치의 레지스터나 내부 메모리를 시스템 주소 공간 일부에 매핑하는 방식이다.
    - CPU는 일반 메모리 접근 명령어(`load/store`)로 장치와 통신한다.
    - 즉, CPU 입장에서는 장치 레지스터가 메모리처럼 보인다.

- Port-Mapped I/O
    - 메모리 주소 공간과 I/O 주소 공간을 분리하는 방식이다.
    - 장치마다 별도의 포트 번호를 부여하고, CPU는 `in`, `out` 같은 특수 명령어로 장치와 통신한다.

xv6는 MMIO를 사용한다. 이는 risc-v가 PMIO를 제공하지 않기 때문이다.

요즘 PMIO가 잘 쓰이지 않는 이유는 역사적으로 I/O 방식이 표준화되었기 때문이다.
과거(~1980년대)에는 컴퓨터마다 장치가 연결되는 방식과 주소 배치가 달라서, 같은 CPU를 써도 주변장치와 소프트웨어가 서로 호환되지 않는 문제가 있었다.

현대에는 PCIe, USB, SATA 같은 표준 I/O 버스가 장치 탐색, 통신 방식, 주소 할당을 담당한다.
따라서 CPU ISA 차원에서 별도의 I/O 포트 공간과 `in/out` 명령어를 유지할 필요가 줄었다.

PMIO는 주로 x86의 하위 호환성이나 레거시 장치 지원을 위해 남아 있다.
