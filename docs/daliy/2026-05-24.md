# 4. Spin Locks

AI 정리: [docs/ai/003_xv6_script_04_spinlocks_20260524.md](/docs/ai/003_xv6_script_04_spinlocks_20260524.md)

- 스케줄러와 락
    - xv6 스케줄러는 단순한 라운드로빈이고, 우선순위 스케줄링은 없다.
    - 그래서 우선순위와 우선순위 기부와 관련된 기능이 없는데, 우선순위 스케줄링 자체가 없으니 이상한 일은 아님.
        - 그래서 해당 내용 관련해서는 Pintos나 CSAPP([쉬운코드 영상](https://youtu.be/gTkvX2Awj6g)) 참고하기
    - 락도 단순한거만 있는데, spin lock과 sleep lock 정도만 있다.
        - sleep lock은 mutex에 가까운 sleep 기반 lock인데, 커널 내부용이고 우선순위 기부 같은 기능이 없어서 mutex는 아니라고 생각함.
    - mutex, semaphore나 condition variable가 없음.
- xv6 구현 특징
    - 핵심은 Pintos나 CSAPP 책의 내용과 크게 다르지 않음.
    - 멀티프로세서 관점에서 비교할만한건,
        - `acquire()`에서 인터럽트를 끄고, `release()`에서 복구함. cnt 기반으로 중첩을 고려해서 복구함.
        - 주요 목적은 데드락을 막는 것.
            - 다른 스레드(혹은 core)의 접근을 막는건 락 자체가 해결하므로 고려대상 아님.
            - 같은 CPU에서 interrupt handler가 같은 lock을 다시 잡으면 데드락 발생.
        - 그래서 함수 내부에서만 끄면 부족하고, lock을 잡은 뒤 `release()` 전까지 critical section 전체에서 꺼져 있어야 함.
        - 스핀락은 짧은 부분에서만 동작하는걸 의도하고 구현의 편의를 위해서 그렇게 함.

# 6. Syscall from Userland

AI 정리: [docs/ai/005_xv6_script_06_syscalls_from_userland_20260524.md](/docs/ai/005_xv6_script_06_syscalls_from_userland_20260524.md)

Syscall이 호출되는 과정과 user process가 실행하는 척 코드를 소개함.

- Syscall
    - `usys.pl`에서 `usys.S`를 생성하고, 컴파일 시에 링크됨.
    - 코드는 정리글 가서 보고, 저게 동작하는 이유를 좀 추가로 적어볼라함.
    - 동작 순서
        1. user C code가 시스템콜 함수를 호출
            - 구현이 C 아닌 어셈블리 코드(`.S`)로 되어있지만, `user/user.h`가 존재하고, 실제 호출 시엔 링크가 되므로 문제 없이 처리됨.
        2. compiler가 RISC-V C ABI대로 인자를 넣고 해당 symbol을 호출
        3. usys.S에 있는 symbol. 기존 레지스터는 유지하고 syscall 번호를 `a7`에 넣은 뒤 `ecall` 실행
        4. `ecall`로 user mode에서 supervisor mode로 trap 발생
        5. 커널의 trap에서 syscall인걸 확인하고 적절한 처리 (여기는 설명 아직 안했으니 넘김)
            - 시스템콜의 인자를 xv6가 RISC-V C ABI와 호환되도록 구현했기 때문에 이런게 가능
            - (trap이므로 다시 `ecall`위치로 가게 되므로, 다음 명령어가 실헹되게 레지스터 조정을 하는 듯함)
        6. 이후 다시 usys.S로 돌아와서 caller에게 결과를 반환
- `initcode.s`
    - 역할은 `/init`을 `exec()`해서 진짜 첫 user program을 시작하는 것.
        - `init`이 무엇인지는 영상에서도 넘어감.
        - 그냥 이런 식으로 시작 된다는걸 소개하기 위함인듯?
    - 강의와 다르게 현재 이 repo에는 커널이 `/init`을 `kexec()`으로 대체 되어있음.
