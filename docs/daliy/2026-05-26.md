# 14. Trap Handling

AI 정리: [docs/ai/013_xv6_script_14_trap_handling_20260525.md](/docs/ai/013_xv6_script_14_trap_handling_20260525.md)

이전에 보여준 자료 기반으로 trap 과정을 설명하는데 간단하게 요약하면

1. trap 진입
   - CPU가 supervisor mode로 바꾸고, 복귀에 필요한 최소 상태만 CSR에 저장한 뒤 `stvec` handler로 이동한다.
   - xv6는 부팅 때 대부분의 trap을 supervisor mode에서 처리하도록 위임해 둔다.
2. user 상태 저장
   - `uservec`이 현재 process의 `trapframe`에 user register와 user PC를 저장한다.
3. kernel 실행 상태로 전환
   - `trapframe`에 준비된 kernel stack, kernel page table, hart id, `usertrap` 주소를 로드한다.
4. kernel 처리
   - `usertrap()`이 trap 원인을 보고 syscall, device interrupt, timer interrupt, page fault 등을 처리한다.
   - timer interrupt라면 `yield()`를 거쳐 다른 process로 이어질 수도 있다.
5. 복귀 준비
   - 다음 trap entry에 필요한 kernel 진입 정보를 다시 `trapframe`에 저장하고, `sret`에 필요한 상태를 준비한다.
6. user 상태 복구
   - `userret`이 user page table로 전환하고 `trapframe`에서 user register를 복원한 뒤 `sret`로 돌아간다.

- `trapframe`은 “user 상태 전체 + 다음 kernel 진입에 필요한 일부 kernel 상태”를 저장하고 있음.
- `trap entry`: user -> kernel로 들어오는 입구, xv6에서는 `trampoline.S`의 `uservec` 라벨
- `trap return`: kernel -> user로 돌아가는 출구, xv6에서는 `trampoline.S`의 `userret` 라벨
