## 한국어 번역

이 비디오는 xv6 운영체제 커널에 대한 연속 강의의 일부입니다. 이 비디오에서는 오브젝트 파일들을 링크해서 이미지 파일을 만들어 내는 과정에 대해 이야기하겠습니다. 구체적으로
kernel.ld 파일에 대해 이야기할 건데, 이 파일은 C 프로그램도 아니고 어셈블리 프로그램도 아닙니다. 대신 링커에게 메모리에 무엇을 어떻게 배치할지를 지시하는 명령들을 담고
있는 링커 스크립트 파일입니다.

먼저 커널이 메모리를 어떻게 사용하는지부터 이야기하겠습니다. 여기 그림에 커널의 코드와 데이터가 메모리에 어떻게 있는지가 나와 있습니다. 링커는 기본적으로 모든 코드를 메모리에
배치하고, 각 것이 메모리의 어디에 갈지를 계산합니다. 실제로 메모리에 집어넣는 것은 아니고, 메모리의 어느 위치로 갈지를 계산만 하는 겁니다. 링커는 보통 C 프로그래머가 크게
신경 쓰지 않는 도구입니다. 대부분의 사용자 수준 프로그램에서는 링커의 기본 동작만으로 충분합니다. 하지만 커널을 만들 때는 더 구체적으로 제어해야 하고, 몇 가지 명령을 추가해야
합니다. 그래서 링커에 이런 명령을 제공하는 파일, 그리고 그 명령에 따라 링커가 무엇을 하는지를 설명하겠습니다. 링커가 하는 일은 오브젝트 파일에 있는 모든 데이터를 가져다
하나의 실행 파일로 합치는 것입니다.

여기 초록색으로 보이는 부분이 커널의 여러 부분에서 나온 오브젝트 파일의 내용입니다. 링커는 이 모든 자료를 메모리의 어디에 둘지 계산한 다음, 나중에 커널을 메모리에 적재해서
실행할 준비가 되었을 때 메모리에 로드될 모든 데이터를 담고 있는 실행 파일을 만들어 냅니다.

사용하는 에뮬레이터 QEMU는 이 실행 파일을 읽어서, 링커가 정해 준 주소들에 맞춰 내용을 메모리에 집어넣습니다. C 프로그램을 컴파일하면 어셈블리 코드가 생성되고, 그 어셈블리
코드는 다시 어셈블 과정에서 오브젝트 파일을 만들어 냅니다. 혹은 우리가 entry.s 파일에서처럼 처음부터 어셈블리 코드를 직접 쓸 수도 있습니다. 어셈블러는 그것에 대해서도
오브젝트 파일을 생성합니다. 오브젝트 파일에는 여러 개의 세그먼트(섹션이라고 부르기도 합니다)가 들어 있는데, 각 세그먼트에는 메모리에서 서로 인접하게 배치되어야 할 데이터가 모여
있습니다. 하지만 컴파일러와 어셈블러는 각 세그먼트가 실제 메모리의 어디에 배치될지는 알지 못합니다.

세그먼트에는 여러 종류가 있고, 각 종류에는 이름이 붙어 있습니다. 예를 들어 .text, 읽기 전용 데이터인 .rodata, 그리고 .data, .bss 같은 이름입니다. 이들이
각각 세그먼트의 이름인지, 아니면 세그먼트의 일반적인 타입 이름인지는 크게 중요하지 않습니다. .text 세그먼트에는 실행 가능한 코드가 들어 있습니다. .data 세그먼트에는
프로그램의 변수들이 들어가는데, 이 변수들은 읽기도 하고 수정도 하며, 초기값이 있을 수도 있습니다. 또 읽기 전용 데이터가 있는데, 그런 종류의 세그먼트에는 초기화되지만 실행
중에는 절대 수정되지 않는 데이터가 들어갑니다. 그래서 읽기 전용입니다. 그리고 bss 세그먼트라는 것도 있는데, 여기에 들어 있는 데이터는 특정 초기값으로 초기화되지 않고,
메모리에 적재될 때 0으로 채워지도록 되어 있습니다. 그래서 이런 세그먼트들은 초기화 데이터 자체를 담고 있을 필요가 없어서, 오브젝트 파일이나 실행 파일 안에서는 꽤 작을 수
있습니다. 실제 데이터가 들어 있지 않기 때문입니다.

이렇게 여러 파일들을 컴파일하고 어셈블한 결과로, 우리가 지금까지 이야기했고 앞으로도 이야기하게 될 모든 파일로부터 많은 세그먼트들이 생깁니다. 여러 개의 text 세그먼트,
data 세그먼트 등이 생기지요. 링커는 이들을 메모리의 어디에 둘지 계산하고, 여기 보이는 2GB 경계 지점부터 배치하기 시작합니다. 그리고 모든 text 세그먼트를 한데
모으고, 모든 data 세그먼트를 한데 모으고, 그 밖의 세그먼트들, 모든 bss 세그먼트, 모든 읽기 전용 데이터 세그먼트를 각각 모아서 배치합니다. 또한 우리가 특별한 이름을
붙여 둔 특수 세그먼트가 하나 더 있는데, trampoline 코드용 세그먼트입니다. 이건 trampoline 섹션(또는 세그먼트)을 위한 것이고, 특별한 위치에 배치해 줘야
합니다. 링커의 커맨드 라인에는 여러 오브젝트 파일을 나열하는데, 각 오브젝트 파일의 세그먼트들이 서로 같은 종류끼리 묶입니다. 즉, 각 오브젝트 파일의 모든 text 세그먼트가
한데 묶이고, 이들은 커맨드 라인에 나열된 오브젝트 파일의 순서에 따라 차례로 배치됩니다.

링커에 넘기는 커맨드 라인에는 entry 코드용 오브젝트 파일이 포함됩니다. 이 entry 파일은 나중에 자세히 볼 텐데, 아주 짧은 어셈블리 언어 파일이지만, 가장 먼저 실행되는
코드입니다. entry의 오브젝트 파일이 커맨드 라인에서 제일 앞에 오기 때문에, 그 코드가 가장 앞에 배치됩니다. 이 파일에는 _entry라는 라벨이 들어 있는데, 파일 안의 첫
번째 명령어에 붙어 있는 라벨입니다. 그래서 그 .text 세그먼트가 제일 먼저 오고, 링커가 가장 앞에 배치합니다. 우리는 실행을 커널의 가장 첫 위치에서 시작하는데, 그게 바로
이른바 엔트리 포인트(entry point)입니다. 그 다음에 링커는 나머지 C 파일들의 text 세그먼트들을 포함시킵니다. 실제로는 여기서 보여 준 것보다 훨씬 많은 C 파일들이
있습니다. 그리고 trampoline 세그먼트라는 특수 세그먼트가 있고, 이것도 적절히 배치한 다음, 각기 다른 오브젝트 파일에서 온 읽기 전용 세그먼트들을 한데 모으고, data
세그먼트들을 모으고, bss 세그먼트들을 모읍니다. 그리고 최종적으로 네 개의 세그먼트를 가진 실행 파일을 만들어 냅니다. 즉, 모든 text 세그먼트들을 하나의 .text
세그먼트로 합치고, 모든 읽기 전용 데이터 세그먼트를 하나로 합치고, 모든 data 세그먼트를 하나로, 모든 bss 세그먼트를 하나로 합칩니다.

이렇게 것들을 메모리에 배치하는 과정에서, 링커는 모든 것의 주소를 계산합니다. 덕분에 이전 단계에서는 채울 수 없었던 여러 정보를 이 시점에서 채워 넣을 수 있습니다. 예를 들어

시점에 링커는 코드로 돌아가서 정확한 숫자(주소)를 삽입하도록 코드를 수정합니다. 또 어떤 변수들을 주소 값으로 초기화할 수도 있는데, 링커는 그 변수의 정확한 위치로 가서 그
데이터를 올바른 주소 값으로 수정하거나 초기화합니다.

실제로 메모리에서 각 것이 어디에 배치될지를 아는 것은 링커뿐이기 때문에, 이런 작업은 오직 링커만 할 수 있습니다.
