저장할 필요가 없습니다.

ra는 리턴 주소(return address) 레지스터입니다. RISC-V는 함수 호출과 리턴을 위해 약간 똑똑한 방식을 사용하는데, 호출이 이루어질 때 리턴 주소를 스택에
푸시하는 대신 이 레지스터에 저장합니다. 그리고 리턴 명령어는 단순히 이 리턴 주소 레지스터의 값을 pc에 다시 복사합니다.

그래서 많은 함수의 경우 아예 메인 메모리에 접근할 필요가 없습니다. sp는 스택 포인터(stack pointer)이고, 스택은 아래 방향으로 성장합니다. tp는 소위 스레드
포인터(thread pointer)입니다. xv6 커널에서는 이 레지스터에 코어 번호, 즉 하트 ID, 하드웨어 스레드 ID가 들어갑니다. 여기서 thread는 아마도 하드웨어
스레드를 의미한다고 볼 수 있겠습니다. gp는 글로벌 포인터(global pointer)입니다. 컴파일러가 사용하며 한 번 설정되면 바뀌지 않습니다.

기본적으로 전역 변수와 공유 변수를 빠르고 효율적으로 접근하기 위해 사용됩니다. 그다음에는 함수 인자를 전달하는 데 사용되는 a 레지스터들이 있습니다. 함수가 어떤 값을 리턴한다면

모든 레지스터는 사용자 모드 코드에서도 접근 가능합니다. 사용자 코드는 언제든지 tp에 다른 값을 써 넣을 수 있습니다. 커널 코드에서 사용자 코드로 넘어갈 때, 커널은 먼저
자신의 모든 레지스터를 저장합니다. 여기에는 tp도 포함됩니다. 그다음 사용자 코드는 일정 시간 실행되다가 어떤 일이 일어납니다. 예를 들어 어떤 종류의 트랩이 발생하면, 그
시점에 커널이 다시 활성화되고, 커널이 가장 먼저 하는 일은

자신의 레지스터를 복원하는 것입니다. 여기에는 tp도 포함됩니다. 그래서 커널 내부에서는 tp가 절대 바뀌지 않습니다. 그리고 여기 두 개의 레지스터가 더 있습니다. 물리 메모리
보호(physical memory protection) 시스템이 있는데, xv6 커널에서는 사용하지 않습니다. 하지만 하드웨어에 존재하기 때문에 어쨌든 다뤄야 합니다. 기본적으로
이 시스템은 supervisor 모드나 사용자 모드에서 실행되는 코드가 물리 메모리에 접근하는 것을 제한할 수 있습니다. machine 모드에서는

메모리를 여러 영역으로 나누어, 특정 영역의 코드가 다른 코드에 간섭하지 못하도록 막을 수 있습니다. 이 시스템의 의도된 용도는 보안 부트스트랩(secure
bootstrapping)과 하이퍼바이저(hypervisor) 코드를 지원하는 것입니다. 하이퍼바이저는 일종의 운영체제 같은 코드이고, 여기서 각 사용자 스레드는 호스트
운영체제(host OS)라고 볼 수 있습니다. 하이퍼바이저의

아이디어는 이 물리 메모리 보호 기법을 사용해서 한 운영체제가 사용하는 메모리를 다른 운영체제와 분리하는 것입니다. 우리의 경우 xv6에서는, machine 모드에서 부팅하는 동안
이 시스템을 설정하고, 물리적인 주메모리 전체를 읽기/쓰기/실행이 모두 가능한 영역으로 표시합니다. 그리고 그 이후에는 이 레지스터들을 더 이상 변경하지 않습니다.
