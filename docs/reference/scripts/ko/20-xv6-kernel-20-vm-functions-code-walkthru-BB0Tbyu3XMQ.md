루프를 시작하기 전에, 마지막 페이지의 주소를 계산합니다. 가상 주소에 size - 1을 더합니다.

여기에서, 우리가 방금 추가한 페이지가 마지막 페이지였는지를 확인하고, 그렇다면 루프를 종료하고 0을 리턴합니다.

그러면 각 가상 주소마다 무엇을 하느냐?

walk를 호출해서, 필요하다면 인덱스 페이지들을 할당하면서 페이지 테이블을 따라 내려갑니다.

여기서 walk의 alloc 인자는 true로 설정되어 있는 것을 볼 수 있습니다.

문제가 생겨서 walk가 null을 리턴하면, 즉시 -1을 리턴합니다. 그렇지 않으면 페이지 테이블 엔트리를 가리키는 포인터를 얻게 됩니다. 여기서 PTE는 페이지 테이블 엔트리를
가리키는 포인터입니다.

그 페이지 테이블 엔트리는 반드시 아직 valid가 아니어야 합니다. 그래서 여기서 우리가 하는 일은 valid 비트를 검사하는 것입니다.

만약 이 비트가 1이면 panic을 호출하고, 문제가 있다고 판단합니다.

그렇지 않다면 이 함수 PA to PTE를 호출합니다. 이것은 매크로 전처리기 함수입니다.

이 함수는 물리 주소를 받아서 페이지 테이블 엔트리를 만듭니다.

여기 물리 주소 그림이 있고, 만약 이 주소가 페이지 정렬된 주소라면, PA는 항상 그렇지만, 오프셋 비트는 전부 0입니다.

PA, 즉 “physical address to page table entry”는 어차피 이 비트들은 무시하지만, 여기 있는 44비트를 추출해서 시프트하고, 이 비트들을 0으로
세트합니다. 이 비트들은 읽기, 쓰기, 실행, valid, 그리고 user 비트입니다. 그리고 PA to PTE는 이것들을 전부 0으로 설정합니다.

그 다음에, 여기서 OR 연산을 통해 퍼미션을 넣습니다. 마지막 인자인 perm에서 가져온 퍼미션을 OR 해서 넣고, 동시에 valid 비트도 세트합니다. 그리고 이렇게 새로 만든
페이지 테이블 엔트리를, 들어가야 할 레벨 0 인덱스 페이지의 해당 위치에 저장합니다.

그리고 이 작업을 각 가상 페이지마다 반복하고, 마지막에 종료하면서 0을 리턴합니다.

다음으로, 커널의 페이지 테이블을 구성하는 함수들을 살펴볼 텐데, 이 함수들은 map pages를 호출하되, KVM map이라는 작은 래퍼(wrapper) 함수를 통해 호출합니다.
이 함수가 하는 일은 그냥 map pages를 호출하는 것뿐이고, 인자들은 페이지 테이블, 가상 주소, 물리 주소, 크기입니다.

순서는 완전히 같지는 않지만, 그리고 퍼미션 인자도 있습니다.

만약 map pages에서 문제가 발생하면, 이 함수는 즉시 panic을 호출합니다.

다음으로, 커널의 페이지 테이블을 생성하고 초기화하는 함수 KVM make를 살펴보겠습니다.

이 함수는 실제 일을 하기 위해 KVM map을 호출할 텐데, 방금 살펴본 작은 래퍼 함수로, 결국 하는 일은 map pages를 호출하는 것뿐입니다.

이 함수는 물리 메모리, IO 장치들에 대한 직접 매핑을 만들고, 트램펄린 페이지(trampoline page)도 매핑하고, 각 프로세스마다 스택으로 사용할 페이지들에 대한 매핑도
만듭니다. 그 부분은 잠시 뒤에 더 이야기하겠습니다. 기본적으로, 여기 그림을 기억한다면, 이 함수는 거기에

설명된 매핑들을 만들어 줄 것입니다. 여기가 물리 주 메모리고, 이쪽이 커널의 가상 주소 공간입니다.

여기서 IO 장치들을 볼 수 있습니다.

커널의 코드와 데이터가 보이고, 물리 RAM이 보이는데, 이 부분은 직접 매핑되어 있습니다. 그리고 다른 것들도 좀 보이죠. 이제 코드를 살펴보겠습니다.

여기가 KVM make의 코드입니다.

이 코드는 페이지 테이블을 새로 만듭니다. 여기에서 최상위 인덱스 페이지, 즉 레벨 2 인덱스 페이지를 할당하고, memset으로 0으로 채워서 엔트리가 하나도 없게 만듭니다.
그리고 그 로컬 변수인 kernel’s page table을 설정하고, 이 값이 이후 모든 KVM map 호출에서 사용됩니다.

이 함수의 마지막 부분에서는 그 포인터를 리턴합니다.

자, 여기까지 해서 최상위 인덱스 페이지를 만들고 0으로 초기화했고, 이제 KVM map을 호출해서 매핑들을 추가하기 시작합니다. 첫 번째는 시리얼 장치, 즉 universal
asynchronous receive transmit unit(범용 비동기 송수신 장치)에 대한 매핑입니다. 이것은 직접 매핑이기 때문에, 가상 주소는 여기, 물리 주소는
저기이고, 크기는 한 페이지뿐이므로 페이지 크기는 그냥 4K 페이지

크기입니다. 그리고 읽기 및 쓰기 가능으로 표시됩니다. 이게 권한입니다.

그래서 이 호출이 이 매핑, 즉 여기 보이는 이 매핑을 만듭니다.

다음 줄에서는 디스크 장치에 대한 매핑을 만듭니다.

역시 한 페이지고, 읽기 및 쓰기 가능입니다.

그래서 이게 여기 디스크 페이지이고, 물리 주소 공간 쪽에 있는 단일 페이지입니다. 그다음에는 platform level interrupt controller(플랫폼 레벨 인터럽트
컨트롤러)가 있습니다. 이것도 직접 매핑됩니다. 크기가 조금 더 큰데, 실제로 4MB입니다.

이것 역시 자기 주소 범위에 직접 매핑됩니다.

마찬가지로 읽기 및 쓰기 가능합니다.

이제 커널을 보겠습니다. 커널은 물리 메모리에 로드되어 있고, 로드된 물리 주소를 kernel base라고 부릅니다. 그리고 e-text라는 다른 주소가 있는데, 이 지점이
데이터가 시작되는 위치입니다. 그래서 먼저 코드 구간에 대한 매핑을 만드는데, 이 부분은 읽기 및 실행 가능하지만 쓰기는 불가능합니다.

이 코드는 kernel base에서 e-text까지, 여기 e-text 주소까지에 해당합니다. 여기서 일어나는 일은, 가상 주소와 물리 주소가 동일하다는 겁니다. 직접 매핑이고,
크기는 e-text에서 kernel base를 뺀 값입니다. 다시 말해 읽기 및 실행 가능으로 표시됩니다.

그 다음에는, 남은 물리 메모리 전체, 즉 여기부터 물리 메모리의 끝, phys top까지는 읽기 및 쓰기 가능으로 매핑됩니다. 여기에 커널의 데이터도 포함되고, 남은 메모리는
kalloc과 kfree 루틴이 사용할 메모리가 됩니다. 여기에서 그 구간을 매핑하는 겁니다. 가상 주소로는 e-text를 주고, 물리 주소도 동일하게 주며, 크기는 메모리
상단에서 e-text까지의 범위입니다.

그리고 이 구간은 읽기 및 쓰기 가능으로 표시됩니다.

다음으로 트램펄린 페이지를 매핑합니다.

이건 직접 매핑이 아닙니다. 대신, 가상 주소는 trampoline인데, 이는 가상 주소 공간에서 가장 높은 페이지의 주소입니다. 바로 여기 있는 이 주소죠.

그리고 이 가상 주소는 트램펄린 코드가 위치한 물리 주소에 매핑됩니다.

이 매핑은 한 페이지이고, 읽기 및 실행 가능으로 설정됩니다.

이제 다음 페이지로 가 보면, 이 함수의 마지막 부분에서 proc_map_stacks를 호출하는 것을 볼 수 있습니다.

다시 이 페이지, 이 다이어그램으로 돌아가 보면, 여기 오른쪽이 커널의 가상 주소 공간입니다. 맨 위 페이지가 트램펄린 페이지입니다.

그리고 그 아래에 여러 페이지들이 있는데, 64개 프로세스 각각에 대해 한 페이지씩 있고, 이 페이지들이 각 프로세스의 스택을 담게 됩니다.

각각의 길이는 한 페이지이고, 각 스택 페이지 사이에는 하나씩 가드 페이지가 끼어 있습니다.

kstack이라는 전처리기 함수가 있습니다.

이 함수는 0부터 63까지의 숫자를 하나 넘겨받고, 이 페이지의 가상 주소를 리턴합니다. 예를 들어 2를 넘기면 바로 이 가상 주소를 리턴합니다. 1을 넘기면 이 주소를 리턴하죠.
즉, 이 함수가 이 페이지들이 가상 주소 공간의 어디에 위치하는지 알려줍니다.

이제 준비가 되었으니, 이 함수에서 proc_map_stacks를 호출합니다.

지금까지의 코드는 모두 vm.c에서 나온 것이었습니다.

하지만 proc_map_stacks는 proc.c 파일 안에 있습니다.

여기 있습니다. 이 함수는 커널 페이지 테이블에 대한 포인터를 인자로 받고, 아무 값도 리턴하지 않습니다. 단지 그 페이지 테이블을 갱신할 뿐입니다.

먼저 프로세스 개수(64개)를 기준으로 반복을 돌 것입니다. proc 구조체들이 들어 있는 proc 배열이 있고, 이 배열을 가리키는 포인터가 있습니다. 이 배열을
순회(iterate)하면 됩니다. 이 루프에서 하는 일이 바로 그것입니다. 64개의 proc 구조체 각각을 순회합니다. 그리고 각 구조체마다

물리 메모리에서 페이지 하나를 할당합니다. 즉, Kalloc 영역 어딘가에서 물리 페이지 하나를 할당해서 스택으로 사용할 겁니다.

그 다음에 그 페이지를 위쪽 어딘가에 매핑할 겁니다. 여기서 다시 트램펄린 페이지와, 가드 페이지들로 분리된 스택 페이지들이 있는 그림을 볼 수 있습니다.

즉, 먼저 자유 메모리(free memory)에서 물리 페이지 하나를 잡습니다. 저 위쪽 어딘가에서요.

그리고 그 페이지로부터 이쪽으로 가는 매핑을 만듭니다. 그림의 화살표들이 사실 마음에 안 드는 게, 다른 곳을 가리키는 것처럼 보이는데,

실제로는 이 화살표들이 자유 메모리 영역 안쪽을 가리켜야 합니다.

그래서 여기서는 각 proc, 각 프로세스마다 페이지를 하나씩 할당합니다. 문제가 생기면 panic을 호출하고, 문제가 없으면, 여기서

0에서 63까지 숫자를 계산해 냅니다. C 언어 문법 때문에 조금 이상해 보이지만, 어쨌든 0부터 63까지 숫자를 계산해서 kstack을 호출하고, 우리가 매핑하고 싶은 가상
주소를 얻습니다. 그리고

바로 방금 계산한 가상 주소와, 실제 물리 페이지의 주소를 인자로 주어 KVM map을 호출합니다. 길이는 한 페이지이고, 읽기 및 쓰기 가능으로 설정합니다.

이것으로 KVM make는 마무리됩니다.

다음으로 두 개의 짧은 함수, KVM init과 KVM init hart를 보겠습니다.

이 둘은 바로 코드부터 보겠습니다.

KVM init은 초기화 도중 코어 0이 한 번만 호출합니다. 즉, 한 코어에서만 호출되며, KVM make를 호출해서 커널의 페이지 테이블을 만들고, 그 포인터를 전역 변수
kernel page table에 저장합니다.

그다음, 초기화 과정의 일환으로 각 코어는 KVM init hart를 호출합니다. 이 함수가 하는 일은 SATP라고 불리는 제어/상태 레지스터를 설정하는 것입니다. 즉, SATP
레지스터에 커널의 페이지 테이블 주소를 써 넣습니다.

이렇게 하면 사실상 페이징이 켜지면서 페이지 테이블이 설치된다고 볼 수 있습니다.

make SATP는 이 포인터를 RISC-V 프로세서가 요구하는 형식으로 약간 변환해 주는 작은 함수일 뿐입니다.

그다음에 fence 명령을 사용해서, 이 제어/상태 레지스터를 변경하기 전에 끝내야 할 일은 실제로 그 전에 모두 수행되고, 그 이후에 해야 할 일은 실제로 그 뒤에 수행되도록
보장합니다.

다음으로 walk address 함수 코드를 보겠습니다.

이 함수는 페이지 테이블을 인자로 받고, 그 페이지 테이블을 사용해서 가상 주소를 물리 주소로 대응시킵니다.

가상 주소는 유효해야 하고, 사용자 모드 접근 권한이 설정되어 있어야 합니다.

또 이 가상 주소는 페이지 정렬(page-aligned)된 주소여야 하며, 함수는 메모리에서 그 가상 주소가 위치한 물리 페이지의 주소를 반환합니다. 문제가 있으면 0을
반환합니다. 이제 walk address의 코드를 보겠습니다.

먼저 에러 체크가 있습니다. 가상 주소가 너무 크면 그냥 0을 반환합니다.

그다음 walk 함수를 가상 주소와 함께 호출해서 페이지 테이블 엔트리의 포인터를 얻습니다. 인덱스 페이지가 존재하지 않는다고 해서 새로 할당하지는 않습니다.

walk가 유효한 것을 반환하면 계속 진행하고, null을 반환하면 곧바로 0을 반환합니다.

그다음 유효 비트가 설정되어 있는지 확인합니다. 설정되어 있지 않으면 0을 반환합니다. 그리고 그 페이지가 사용자 모드에서 접근 가능한지 확인하기 위해 해당 비트를 검사합니다. 이
비트가 설정되어 있지 않으면 역시 0을 반환합니다. 마지막으로 작은 PTE to physical address 함수를 호출해서, 여기서 페이지 테이블 엔트리를 가져오고,

그 안에서 물리 페이지를 가리키는 포인터를 추출해서 물리 주소를 반환합니다.

UVM create 함수는 빈 가상 주소 공간을 생성하고 그 포인터를 반환하는 데 사용됩니다. 즉, 루트, 곧 2단계 인덱스 페이지만 있는 페이지 테이블을 하나 만듭니다.

코드를 보죠.

UVM create는 페이지 테이블을 가리키는 포인터를 반환합니다.

이 함수는 사용자 프로세스를 위한 가상 주소 공간을 만들 때만 사용되므로 이름이 UVM create입니다. 여기서 페이지 하나를 할당하는데, 그게 2단계 인덱스 페이지, 루트
페이지가 됩니다. 문제가 생기면 null을 반환합니다.

그렇지 않으면 memset을 호출해서 루트 인덱스 페이지 안의 모든 페이지 테이블 엔트리를 0으로 초기화하고, 그 페이지에 대한 포인터를 반환합니다.

UVM init 함수는 첫 번째 프로세스를 위한 가상 주소 공간을 만드는 데 사용됩니다.

하지만 기본적으로는 아주 짧은 프로그램으로, exec 시스템 콜을 한 번 실행해서 또 다른 프로그램을 호출하고, 전체 시스템이 돌아가기 시작하도록 만듭니다.

이 어셈블리 언어 프로그램은 따로 어셈블하고, 그 바이트들을 전부 추출합니다. 실제로는 52바이트입니다.

그리고 16진수 형태로, 커널 코드 안의 init code라는 이름의 바이트 배열에 직접 지정해 둡니다. 이 함수가 할 일은 페이지를 하나 할당하고, 그 페이지 안에 이 바이트들을

페이지 테이블에 대한 포인터, 이전 크기(원래 크기), 그리고 새로운 크기를 인자로 넘기고, 이 함수는 새로운 크기를 반환합니다.

페이지들은 가상 주소 공간에 추가되는데, 그 과정에서 K alloc을 호출해서 새로운 물리 페이지들을 얻고, 그 페이지들을 0으로 초기화한 다음, map pages를 호출해서

페이지로 넘어갑니다. 하지만 문제가 생기면, 방금 여기서 할당한 페이지를 K Free를 호출해서 해제합니다. 그리고 나머지 이미 할당한 페이지들도 전부 해제합니다. 다시 말해,

각 페이지마다, 페이지 테이블 엔트리를 찾아가서 valid 비트를 클리어합니다.

이런 페이지 테이블 엔트리들의 경우, 실제로 포인터가 있다면 valid 비트는 1이어야 하고, 읽기, 쓰기, 실행, user 모드 비트들은 0이어야 합니다.

아래쪽 코드를 보면, 페이지 테이블 엔트리(PTE)가 유효하다면, 반드시 어떤 데이터 페이지를 가리켜야 하고, 그 데이터 페이지는 적어도 읽기 가능이거나 쓰기 가능이거나 실행
가능해야 하며, 필요하다면 사용자 모드 비트도 설정되어 있어야 합니다. 즉, 유효 비트를 제외한 나머지 비트가 모두 0이면 안 됩니다. 지금 여기서 하는 검사는 바로 그 점을
확인하는 것입니다. 유효 비트 하나만이 아니라 그 밖의 비트들 중에 뭔가 하나라도

설정되어 있는지 검사하는 겁니다.

그리고 이 페이지 테이블 엔트리에 대해 우리가 할 일은 그냥 0으로 설정하는 것인데, 이렇게 하면 유효 비트를 포함한 여러 비트가 지워집니다.
