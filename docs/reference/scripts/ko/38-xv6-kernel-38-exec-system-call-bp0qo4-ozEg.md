보고, 이것이 켜져 있으면 페이지 테이블 엔트리의 쓰기 가능 비트도 켭니다. 그리고 이렇게 만든 새 권한 값을 반환하고, 이 값이 uvm_alloc 함수의 인자로 넘어갑니다.

이제 load_segment 함수를 살펴봅시다. 여기 load_segment 함수가 있고, page table 포인터를 인자로 받습니다. 이 페이지 테이블은 지금 생성 중인 실행

정렬되어 있어야 하고, 또 가상 주소 공간에서 실제로 데이터를 쓸 페이지들은 모두 이미 존재해야 합니다. 만약 어떤 문제가 생기면 -1을 반환하고, 그렇지 않으면 0을 반환합니다.

정리하자면, 새 가상 주소 공간을 설명하는 페이지 테이블 포인터뿐 아니라, 데이터를 로드할 주소(va)도 인자로 받고, ip는 실행 파일의 inode를 가리키며, offset은 그
파일에서 우리가 바이트를 가져올 위치를 나타냅니다. size는 가상 주소 공간으로 옮길 바이트 수입니다. 이 함수에는 루프가 하나 있고,

이 루프의 각 반복마다 파일에서 한 페이지 분량의 데이터를 읽어서 가상 주소 공간으로 옮깁니다. i는 지금까지 옮긴 바이트 수를 나타냅니다. 우리는 페이지 크기 단위로 반복하면서,
size 바이트를 다 옮길 때까지 루프를 도는 것입니다. 먼저 하는 일은, 가상 주소 공간을 살펴보면서 다음 데이터 덩어리를 어디로 옮길지 결정하는 것입니다.

그래서 walkaddr를 호출하고, 가상 주소에 i를 더한 값을 넘깁니다. i는 지금까지 옮긴 바이트 수입니다. walkaddr는 그 가상 주소가 매핑된 커널 메모리 안의 물리
주소를 돌려줍니다. 물리 주소를 얻고 나면, 실제로 유효한 페이지가 있는지 확인합니다. 이미 uvm_alloc을 호출했기 때문에 그 페이지는 가상 주소 공간 안에 존재해야 합니다.

공간이 충분한지 확인하고, 충분하지 않으면 여기에서 에러 메시지를 출력합니다. 그다음 앞으로 얼마나 많은 바이트를 더 옮겨야 하는지를 계산합니다. i는 지금까지 옮긴 바이트
수이고, 남은 바이트 수가 한 페이지 분량보다 작다면 전체 한 페이지를 옮기지 않고, 옮길 바이트 수를 size - i로 계산합니다. 그렇지 않으면

이제 exec 함수로 다시 돌아가 봅시다. 여기 이 루프가 프로그램 헤더를 모두 순회하는 부분이고, 각 헤더마다 하나의 세그먼트를 로딩합니다. 이 루프가 끝나면 실행 파일에 대한

했던 일이기 때문에 이 문장은 불필요합니다. 그다음 기존 가상 주소 공간의 크기를 캡처하고, 이 값을 나중에 사용할 겁니다. 그다음 이 부분이 무엇을 하는지 보겠습니다.

이 페이지들은 uvmalloc에 의해 읽기 가능하고 사용자 모드에서 접근 가능하도록 표시됩니다. 그리고 이번 uvmalloc 호출에 넘긴 이 새로운 인자는 페이지들을 쓰기
가능하게도 표시합니다. 그래서 이 페이지들을 사용자 모드에서 접근 가능하도록, 읽기 및 쓰기가 가능하도록 설정할 수 있습니다. 다음으로 하는 일은 uvmclear를 호출하는
것입니다. size 포인터에서 두 페이지를 뺀 주소를 인자로 넘깁니다. 이 시점에서 size 포인터는 두 페이지만큼 증가해 있으므로, 두 페이지를 빼면 guard 페이지를 가리키게
됩니다. uvmclear를 호출하면 이 guard 페이지를 사용자 모드에서 접근 불가능하게 표시합니다. 그리고 사용자 모드 프로그램이 스택을 확장할 때, 스택은 아래 방향으로
자라다가 한 페이지를 넘어가면 이 guard 페이지에 접근을 시도하게 되고,

그 순간 사용자 프로그램이 중단됩니다. 다음으로는 스택 포인터를 캡처해야 합니다. 스택은 비어 있고 아래 방향으로 자라게 될 것입니다. 또한 stackbase라는 변수도
캡처하는데, 이 함수 안에서 스택에 데이터를 push하다가 스택을 넘치는지를 감지하는 데 사용할 수 있습니다. 여기에서는 사용자 모드 비트를 클리어하고, 여기에서

스택 포인터와 stackbase 포인터를 캡처합니다. exec 함수를 계속 보겠습니다. 다음으로 할 일은 인자 문자열들을 처리하는 것입니다. 기억해 두어야 할 점은 exec 함수가
argv라는 배열에 대한 포인터와 함께 호출된다는 것입니다. 그 배열에는 문자열들에 대한 포인터들이 들어 있고, 각 문자열은 커널 공간의 별도 페이지에 배치되어 있습니다. 우리가
도달하고자 하는 모습은 다음과 같습니다.

여기 스택 그림이 있고, 처음에는 빈 스택에서 시작합니다. 스택은 이 방향으로 아래로 자라날 것입니다. 여기서 네 개의 인자 문자열 각각을 스택 위에 push하고 싶습니다. 그리고
그 문자열들을 가리키는 포인터들로 이루어진 배열도 스택에 push하고 싶습니다. 그런 다음 새 프로그램의 main 함수에 argc(이 예에서는 4가 될 것)와

argv(문자열들을 가리키는 포인터 배열에 대한 포인터)를 넘길 것입니다. 이제 코드를 따라가 보겠습니다. 먼저 argc라는 변수로 인자의 개수를 셉니다. 0에서 시작해서 argv
배열을 순회하면서, 각 문자열을 스택에 push할 것입니다. 제일 먼저, 인자가 너무 많지 않은지 확인하고, 너무 많으면

bad 레이블로 갑니다. 그다음 문자열을 보고 길이를 계산한 뒤, 마지막의 널 종료 바이트를 위해 1을 더합니다. 그리고 스택 포인터에서 그만큼을 뺍니다. 이때 스택 포인터가

들어 있는 문자열에 대한 포인터가 있고, 여기에는 문자열 길이와 널 바이트를 포함한 길이가 있습니다. 그리고 현재 스택 포인터 위치로 복사할 것입니다. 이 그림에서 작은 눈금들은

우리는 문자열의 길이를 계산하고, 스택 포인터를 다음 16바이트 경계까지 내린 뒤, 그 위치에 문자열을 복사합니다. 이 과정에서 문자열 뒤에 몇 바이트는 사용되지 않은 채로 남을
수도 있습니다. 이제 ustack이라는 다른 변수가 있습니다. exec 함수의 로컬 변수이고, 방금 스택에 push한 문자열의 포인터를 이 배열에 저장하고 싶습니다.

바로 그 작업을 여기서 하고 있습니다. 제가 여기 ustack 배열을 그려 두었는데, 보통은 배열을 위쪽에 첫 번째 요소가 오고 아래로 내려가면서 인덱스가 증가하는 식으로
그렸습니다. 하지만 이번에는 반대로 그렸습니다. 여기 위쪽이 첫 번째 문자열에 대한 첫 번째 요소입니다. 이렇게 그린 이유는 스택이 아래로 자라는 모습을 보여 주기 위해서인데,

아래쪽에 낮은 주소, 위쪽에 높은 주소가 오기 때문입니다. 그래서 첫 번째 문자열에 대해 ustack 배열에 포인터를 하나 추가하고, 나머지 문자열들에 대해서도 마찬가지로
추가합니다. 이 루프를 돌면서 각 인자에 대해, 문자열을 스택에 push하고 그 포인터를 ustack 배열에 저장합니다. 마지막에 모든 문자열 처리가 끝나면,

마지막 포인터 뒤에 널 포인터를 하나 저장합니다. 이 그림에서 보이는 이 널 포인터가 그것입니다. 이제 이 ustack 배열 자체를 스택 위에 push해야 합니다. 여기서 배열의
크기를 계산합니다. 요소 개수에 마지막 널 하나를 더한, 즉 4 + 1에 각 포인터의 크기를 곱한 값입니다. 그리고 그만큼 스택 포인터에서 빼고, 이전과 마찬가지로 이 줄에서 스택
